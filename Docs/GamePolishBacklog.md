# 《潮线之上》游戏优化清单

复核于 2026-11-15，基于 `f0768f0` 和 Unity 6.6（`6000.6.6f1`）。功能完成情况见[项目进度与待办](ProjectProgress.md)。

当前最影响观感的是顶栏拥挤、地表颜色和质感过于均匀、建造时格网盖住大部分画面。最影响操作的是淡水误放、拖路断开后仍继续扣费铺设，以及读档快捷键与测试功能冲突。建议先用主岛的一段「前哨平地—溪流池塘—低岩岸码头」做成质量样板，再把材质、植被、灯光和界面规则铺到整张地图。

**优先级** · P0 影响正确操作或完整试玩，P1 是下一版的主要体验提升，P2 在核心流程稳定后完善。

## 界面和镜头

| 优先级 | 当前问题 | 改完怎么验收 |
| --- | --- | --- |
| P0 | **顶栏遮挡。** 1600×1009 实机截图里，天气控件压在木材数量上，时钟和天气各画了一次太阳。 | 还原参考图的薄、贴边、半透明顶栏。左侧天气、时钟、暂停和 1×/2×/3×，中间科技、文化，右侧四项简洁的「图标＋数量」、更多资源和功能按钮。1280×720、1920×1080 和当前窗口下逐个点按。 |
| P1 | **建造菜单。** 卡片的缩略图底色、亮度和主体大小不一致，面板在建造时遮掉不少可用画面。 | 缩略图统一取景与光照，名称、占地、木材费用与锁定原因容易扫读。切换分类、预览和旋转时，放置区域及当前费用一直可见。 |
| P1 | **界面状态和提示。** 科技、文化、仓库、船只、居民和灯塔的面板密度不一致，操作结果有时只出现在一行状态文本里。 | 统一字体、图标和选中样式。主操作、不可用原因、关闭和取消位置稳定。缺料、放置失败、研究完成、船到达等都有短提示。点击面板不会同时下达地图指令。 |
| P1 | **相机。** 主岛开场构图已有基础，跨岛、跟船、定位灯塔后的实际取景需复测。现有夜景验证图里塔顶出框，面板遮住塔身。 | 开场框住主岛和可建区，旋转、缩放与拖动连续。聚焦副岛、船和灯塔时主体完整入画，关闭面板或跟随时能回到合理视角。 |
| P1 | **新玩家指引。** 任务页已有入口，开局仍缺从第一个建筑到出海的操作指引。 | 新游戏前 15 分钟内依次看得懂在哪建、为何建不了、下一步研究什么、去哪个码头登船。进度随实际操作更新，提示可跳过或回看。 |
| P2 | **首页、设置和暂停。** 首页推镜、海面与雾已有，设置用量与过渡反馈需要统一复测。 | 首页背景强调洪灾后的世界；推镜与漂雾过渡平稳，小屏下菜单不盖主体。游戏内暂停和设置可从键盘返回，显示、音量等选项重启后保持。 |

## 建造、道路与靠岸

| 优先级 | 当前问题 | 改完怎么验收 |
| --- | --- | --- |
| P0 | **淡水误放。** Unity 中对 147 个完全位于淡水下面的格子取样，72 个通过居民小屋放置判定，87 个通过道路判定。用正式放置入口已在其中一格建出小屋。 | 溪流和池塘使用明确的淡水判定，普通建筑、道路和人物陆地目标避开水面。岸边干地、海上设施与可用码头保留正确的放置方式。 |
| P0 | **拖路遇阻仍铺。** 实测拖过中间被占用的格子，路段在障碍前后分别铺出，中间断开。 | 拖动先预览整段和费用，遇到阻挡时清楚标出停点。完成一次拖放之后道路连通、已有段不重复付费。检查四个方向的端头、直路、转角、T 字和十字。 |
| P1 | **格网太抢画面。** 建造截图里白格和橙格遍布整岛，连池塘上方都有格线。 | 全岛和山体仍纳入格网，只在选中设施准备放置、拖路或操作指定工具时显示。附近和当前占地更清楚，远处线条淡化；陡坡及禁建区有明确状态，海格在需要时平滑接上岸格。 |
| P1 | **模型、地基和实际占地。** 普通建筑预览会旋转，代码中的占地和找平仍使用初始宽深；大体量建筑、陡坡及路边摆放值得集中复测。 | 至少用 2×4、4×3、10×12 三种矩形试四个方向。预览、实际碰撞、地基、道路避让和读档恢复一致。缓坡用局部基础贴地，山体轮廓完整。 |
| P1 | **低岸码头的衔接。** 当前专项只验证了一个低岸点；新岸线下，台阶、甲板、泊位和船员路线需要合起来验。 | 三岛各测可用的岸段和朝向。台阶接到干地，角色可走上甲板和登船，船体有离岸余量；浪花、坐标吸附和水面格网不会引导玩家放进岩石。 |
| P1 | **施工和拆移反馈。** 已有四阶段模型，常用视角下还需把筹备、开工、进度和完工表现清楚。 | 卡片与建筑面板显示成本和剩余进度；开工和完工有短音效或状态变化。移动、取消和拆除分别核对占地、退款、邻接和遮住的植被。 |

## 岛屿、美术和动效

| 优先级 | 重点 | 优化方向与可见结果 |
| --- | --- | --- |
| P1 | **主岛地形与近看材质** | 实机近景里浅绿地表过于一致，岩壁锐角和灰纹很突兀。保留开阔的建设平地，用高低起伏、可辨的沟谷、岩脊和自然的草土岩过渡增加层次。正常与最近视角都检查纹理大小、重复度和坡脚接缝。 |
| P1 | **草、树和灌木** | 绿色区域铺低矮、密集的细草，黄土地和裸岩稀疏或留空，草地纹理与近看的草叶衔接。以早期认可的树形和比例为参照，混合针叶、阔叶、幼树和林缘灌木。复查树根贴地、叶色别过黄、林缘疏密和施工后的占地清理。 |
| P1 | **岩石与泉眼** | 泉眼附近用较深的湿岩，把岩块与山坡、出水口连起来。岛上保留几处一眼能认出的较大岩块作为未来采石点。对比人物和建筑检查尺度、接触阴影和穿插。 |
| P1 | **小溪和池塘** | 从山坡出水，沿弯曲地势汇入池塘。用同套淡水底色，按浅滩和深水改变明暗，留出流向差异；入口平滑，补齐河床和岸坡贴合。沿源头、中段、入池处和池心从近、远两个距离看一遍。 |
| P1 | **海面、岸线和远景** | 现有海面有浪与泡沫，俯视截图里细纹和亮边较均匀，容易呈规律图案。把外海浪、岸边扰动、岩礁泡沫和船尾迹做出尺度差。保留洪灾后岩岸设定和可接岸坡段，全图无沙滩。远景用岛屿层次与薄雾交代环境。 |
| P1 | **东岛废船与救援艇** | 新版自动选在东岛鞍部。按之前确认的原搁浅区域定位，以新地形核对船底接触和破损轮廓；清理碰到船体的植被。救援艇在水面有正确的吃水、停泊朝向和离岸间隙，全图只出现各自应有的一艘。 |
| P1 | **人物比例与动作** | 新人物近景已有细节，常用镜头下体量小、辨识度低。补足姓名或轻量选中反馈，拉开两名船员的剪影与装备，补顺站立、走跑、停转、上下船的动作和脚底接触。 |
| P1 | **昼夜和坏天气可读性** | 保留阴天、海雾和暴雨的氛围。用当前地图和同一镜头逐一验收正午、黄昏、23:00 晴夜与夜间雷雨，确认山地、人物、道路及建造红绿状态看得清；比对 Game 视图与 Editor 预期，避免调整全局亮度后白天泛亮。 |
| P1 | **偏大的飘落物和黄色圆柱** | 这次没有稳定复现这两件物体。飘落物先按天气和镜头距离定位到实际对象，确认是落叶后再按叶片比例缩小。黄色圆柱出现时记录位置与对象来源，辨认后修正占位外观或位置。 |
| P2 | **建筑与灯塔的共同美术风格** | 统一建筑比例、材质粗糙度、屋顶与边角细节，让渔业、救援和公共设施在俯视下可辨。灯塔保留阶段查看入口，实测从废墟到首次点亮的完整构图、脚手架变化和夜间信标。 |

## 玩法、进度和声音

| 优先级 | 待优化 | 改完怎么验收 |
| --- | --- | --- |
| P0 | **可恢复的存读档。** F9 同时绑了资源补满；建筑与道路进度、在研项目和法令缺字段，命名整理前的建筑还有兼容风险。 | 保存一局含在建建筑、道路、旋转码头、研究队列、灯塔、船员和货物的游戏。退出后继续，库存、占地与施工进度对得上；验证旧名称、取消加载及坏档提示。 |
| P0 | **第一段救援任务。** 已有船和码头，默认场景的打捞、遇险信号未启用。 | 新开局从接信号到登船、出航、现场交互、返航交接和任务结算走通一次。界面能看清任务目标和接回的人或货物去向。 |
| P1 | **两种驾驶方式。** 自动航行会避开不通的水路。手动驾驶直接更新船的位置，与岸线碰撞、燃料耗尽和靠泊提示还需验收。 | 自动与手动都在同一段浅岸试靠，验证船体、路线、掉头、燃料耗尽、取消航线和重新靠泊。人员登船后有名单和可出航反馈。 |
| P1 | **生存开局与资源链。** 初始物资和基础发电仍用 `999` 测试值，砍树、采石、补给来源及生产反馈要连起来。 | 用有限随队物资跑一局，在可理解的消耗下建前哨，过渡到稳定淡水、食物和供电。仓库显示存量、容量与产消变化，停产时指出缺水、缺电或缺原料。 |
| P1 | **模拟节奏。** 核对暂停和 1×/2×/3× 对建造、研究、人口消耗、航行及任务计时的影响。 | 暂停时弹窗和镜头仍能操作，模拟状态按预期停住。加速后的工程、研究、消耗和任务在同一规则下推进。 |
| P1 | **声音层次。** 已有 1 首首页音乐、4 首轮换曲和 5 套基础天气环境声；扩展天气当前共用部分声音。 | 为海雾、暴风潮、冻雨和暴雪配合适的环境层，加入脚步、停泊、操作和施工反馈。调整音乐、天气、音效音量时互不抢声，切天气无突变。 |
| P2 | **剧情、文化与长期变化。** 有开场概念图、研究和法令面板，进入场景后的章节与长期反馈仍要补齐。 | 把支援补给和区域救援接到可玩章节，法令影响人口或生产，海况与长期涨水影响岸线选择。稳定首张地图后再用同一套规则验证新岛。 |

## 性能和试玩验收

| 优先级 | 要优化的场景 | 验收方式 |
| --- | --- | --- |
| P1 | **近景草地与远景群岛。** 草、树、岩石、海面同时可见时记录渲染开销，再定可见距离、遮挡和批处理规则。 | 同一台机器、1080p 下记录初始入场、近景旋转和远景看全三岛的帧时间与内存。草量提高后核对切换距离时没有明显跳变。 |
| P1 | **高负荷操作。** 雷雨、连续铺路、多处施工与自动航行需要组合验证。 | 从开局运行到多处施工和 3× 雷雨，检查明显卡顿、重复报错、保存加载耗时和内存异常增长。 |
| P2 | **下载和发布。** 资源重新命名、Git LFS、首次导入与独立构建需要在干净环境下走一遍。 | 新检出项目能补齐资源，按 README 打开 `Prototype`；Windows 试玩包完成首页、建造、变天、救援和读档。 |

下一版采用同一局做验收。先在主岛建研究站与低岸码头，拖路绕开障碍并试一次池塘边放置，随后让两名船员登船并完成第一次救援，最后返航保存、重启恢复。画面以常用俯视距离为主，同地点保留最近视角和夜间对照。
